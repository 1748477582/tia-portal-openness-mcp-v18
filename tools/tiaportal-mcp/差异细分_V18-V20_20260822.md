# TIA Portal Openness MCP — V18 ↔ V20 差异细分报告

> 生成日期：2026-08-22
> 范围：仅差异细分（A 阶段），不改代码。下一阶段 B（bin-v20 构建骨架）/ C（mcp.json 切换）待确认后执行。
> 数据来源：工程源码实测（`tools/tiaportal-mcp/src/TiaMcpServer/`），非记忆推演。

## 0. 核心结论

工程**已具备三版本共存骨架**（V18 / V20 / V21），并非从零做兼容。差异通过**四种互补机制**处理，而非单一 `#if` 守卫。V18 与 V20 之间真正的**功能断层**集中在 3 类：Unified HMI、Documents(S7DCL) 导出、Hardware HMI 连接（V21+）。其中 V20 相对 V18 **净增能力**，V18 靠垫片/运行时探测兜底，代码侧基本已闭环——剩余问题主要是 **V20 csproj 的配置不对称**（缺 `appsettings.json` 复制与 `InternalsVisibleTo`）。

**实测补充**：当前 `bin-v18/Release/net48/` 与 `bin-v20/Release/net48/` 下均**未检出 `appsettings.json`**——V18 虽有复制项但实际产物缺失（疑似旧构建遗留或路径问题），V20 则根本无此配置。这是 B 阶段构建时必须修复的硬伤。

## 2. 四种差异处理机制（已实证）

### 模式 A — 编译守卫 `#if !TIA_V18`（强排除）
- **作用**：V18 编译期直接剔除，工具在 V18 完全不存在。
- **范围**：**仅 23 个工具，全部集中在 `ModelContextProtocol/McpServer.PlcSoftware.cs`**。
- **内容**：Unified HMI 系列工具（`EnsureUnifiedHmiScreen` / `EnsureUnifiedHmiTagTable` / `EnsureUnifiedHmiTag` / `EnsureUnifiedHmiScreenItem` / `ApplyUnifiedHmiScreenDesignJson` / `EnsureStartStopUnifiedHmi` 等）。
- **注意**：`[McpServerTool]` 特性被守卫，但**方法体未守卫**——V18 下方法仍编入（不可见、不可调用），底层 `Portal.EnsureUnifiedHmiScreen` 在 V18 会因缺 API 运行时失败。这是安全的，因为工具不可见。
- ⚠️ **记忆修正**：家规记忆称"23 个 `*UnifiedHmi*` 工具用 `#if !TIA_V18` 守卫隐藏"——实际 23 个确为 Unified 相关，但**全部在同一文件**，且 `UnifiedHmi` 字符串还出现在 `Program.*` / `Hmi*Builder` / `McpGuides` 等大量文件，那些**未被守卫**（靠运行时探测或条件逻辑）。

### 模式 B — 兼容垫片 `Siemens/V18CompatShim.cs`（V18 专属 `#if TIA_V18`）
- **作用**：在 V18 上手动声明 V20+ 才原生存在的类型，使 Documents 工具能在 V18 编译通过。
- **垫片类型**：`ImportDocumentOptions`、`DocumentResultState`、`TransferResultState`、`DocumentImportResult`、`DocumentExportResult`、`TransferResult`、`HW.TransferResultMessage`。
- **代价**：垫片是"空壳"——V18 下调用这些 API 实际不可用（运行时走异常/降级），仅保证编译。

### 模式 C — 运行时探测 `if (Engineering.TiaMajorVersion < 20)`（软降级）
- **作用**：代码编入所有版本，运行时按连接到的 TIA 版本分支，低版本返回 null / 抛 `McpException`。
- **分布**（实测计数）：
  - `Siemens/Portal.Blocks.cs`：**4 处**（含 `ExportBlocksAsDocuments` 在 `<20` 直接 `return null`）
  - `Siemens/Portal.Helpers.cs`：**1 处**（`>= 19` 分支）
  - `ModelContextProtocol/McpServer.Documents.cs`：`ExportAsDocuments` 抛 `McpException("requires TIA Portal V20 or newer")`
- **关键工具**：`ExportAsDocuments`（SIMATIC SD / S7DCL 人类可读导出）——这是 V18 **缺失**、V20 **净增**的核心能力，家规记忆里的"无 .s7dcl 人类可读 SCL 导出"即指此。

### 模式 D — 能力中心 `Siemens/Capability.cs`（显式可查询）
- **作用**：单一事实源，避免散落静默 no-op。模型启动时可先查询版本能力。
- **`TiaFeature` 枚举**（实测）：
  - `HardwareHmiConnection` — **MinVersion = 21**（V20 不支持，需 V21+）
  - `DocumentExport` — **MinVersion = 20**（V18 不支持，V20+ 支持）
- **API**：`IsSupported()` / `RequireSupported()`（抛 `NotSupportedOnVersion`）/ `Snapshot()`（Bootstrap 广告用）。
- **评价**：这是最干净的兼容模式，建议后续将模式 A/C 的散落逻辑逐步收敛到此。

| 指标 | 实测值 | 家规记忆值 | 偏差 |

## 4. 能力断层矩阵（V18 vs V20）

| 能力 | V18 | V20 | 差异处理模式 | 备注 |
|------|-----|-----|------|------|
| 常规 PLC 块读写/导入导出(SimaticML) | ✅ | ✅ | — | 共有，无差异 |
| Unified HMI 工具族（23个） | ❌ 编译排除 | ✅ | A | V18 不支持 Unified |
| Documents / S7DCL 导出 | ❌ 运行时拒绝 | ✅ | B+C+D | V18 靠垫片编译、运行时降级 |
| Hardware HMI 连接(V21+) | ❌ | ❌（需 V21） | D | V20 仍不支持，非 V18↔V20 断层 |
| 常规 Classic/Comfort HMI | ✅ | ✅ | — | V18 走此族 |
| TO 轴/驱动/编译/诊断 | ✅ | ✅ | — | 共有 |
| 版本自路由(EngineRouter) | ✅ | ✅ | — | 三版本统一机制 |

**净结论**：V18↔V20 之间，V20 相对 V18 **只净增 Unified HMI + Documents(S7DCL)** 两类能力；其余差异为运行时探测软降级。V20 本身不引入破坏性 API 变更（Hardware HMI 连接是 V21 才有的，不属于本次 V18↔V20 范围）。

### 7.3 智能路由核查结论（方案 X 核心已具备）
用户要求的"最小侵入兼容"路线图中，"自动检测版本 + AssemblyResolve 动态加载 + re-exec 兄弟 exe"在工程里**已实现大半**，无需从零写：

- **`Engineering.DetectTiaMajorVersion`**（Siemens/Engineering.cs:70）：注册表 `TIAP*` + 文件系统 `Portal V*` 扫描 + env 变量，取最高可用版本——即路线图"检测已安装版本"要求。
- **`Engineering.Resolver`**（Siemens/Engineering.cs:25）：`AssemblyResolve` 事件处理器，从 `PublicAPI\V{ver}` 递归加载 Siemens.Engineering DLL——即路线图"注册程序集解析器"要求。
- **`EngineRouter.TryRedirect`**（Siemens/EngineRouter.cs:83）：启动时若 `DetectTiaMajorVersion()` 与 `CompiledTiaMajorVersion` 不符，re-exec 对应版本兄弟 exe（stdio 继承）——即路线图"自动重启 MCP 服务器"要求。
- **`Program.Main:127`**：已调用 `TryRedirect` 且位于 CLI verb 分发与 MCP host 之前，**CLI 与 MCP 两条路径均被路由覆盖**。

**因此方案 X 落地的实质增量是**：
1. 确保 `bin-v20` 也构建出来（否则 V18 exe 在 V20 机器上 re-exec 失败会回退到"跨版本 DLL 加载"而崩溃）——即本次构建验证。
2. D7：测试项目支持 V20（已完成，见 7.4）。
3. 路线图中"去掉硬编码 DLL 绝对路径→改 NuGet"的前提**不成立**：csproj 已用 NuGet 包（`Siemens.Collaboration.Net.TiaPortal.Packages.Openness` 18/20），无绝对路径引用。
4. 路线图"Compile 委托签名变化"**在本工程不存在**：Compile 统一走 `CompileAndDiagnosePlc`，无版本分支；V20 专属 `#if` 块仅 2 处（`Portal.Devices.cs` 的 V18||V20 共用逻辑）外加 `EngineRouter`/`V18CompatShim` 符号。
